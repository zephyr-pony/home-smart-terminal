# 硬件到位前的准备清单

ESP32 到货前能做的、必须做的、以及「等硬件再说」的分开列。按「是否卡住真机验收」排优先级。

现状（2026-11-23）：服务端与 Web 控制台已可用；小智服务端在本机 Docker 跑过，
MCP 接入点与 `_meta` 已验证；**反向提醒（服务端→设备）还没做**；手机推送受 HTTPS 限制。

---

## P0：不做就会在真机前卡住

### 1. 反向提醒（方案 A）

- 为什么：MCP 只能设备→小马，提醒到不了客厅音箱。没有它，设备只是一问一答。
- 做什么：`docs/device-reminders.md` 的清单（小马侧 4 处 + 小智 fork 3 个钩子）
- 无硬件可验：数字人测试页就是设备连接
- 依赖：无

### 2. 延迟目标：现在差得很远

`docs/xiaozhi-setup.md` 2026-11-21 的实测（aisp）：

| 环节 | 耗时 |
|---|---|
| ASR | 0.2–0.3 s |
| 带工具的一轮决策 | 2.0–3.5 s |
| 首句 TTS（闲聊） | 8.3 s |
| 整轮（带工具） | 14.0 s |

同一套代码换官方 `deepseek-flash`：首句 2.8 s、整轮 11.2 s。也就是说**模型路由是主要变量**，
而当前决定是不做官方/aisp 分流。这件事必须在买硬件前拍板，否则设备到手第一天就会觉得「慢得没法用」。

要做的事：

- [ ] 用现在的代码复测一轮（11-21 之后加了确认、校验、事实史，数字会变）
- [ ] 定验收线（建议：P95 首句 ≤ 3 s、工具查询 ≤ 5 s；打断响应 ≤ 0.5 s）
- [ ] 不达标时选一条：换模型/路由、砍上下文、查询改单轮、预合成固定话术
- 待决策：D43

### 3. 唤醒词与固件变体

- 固件用 ESP-SR 的 WakeNet，内置唤醒词是「你好小智」这类；叫「小马」大概率要**自定义唤醒词模型**
  （Espressif 有定制服务/工具链），不是改一行配置。
- 要在下单和刷机前定：用内置唤醒词、还是做「小马」模型、还是先双唤醒词过渡。
- 同时定 OTA/WebSocket 地址（局域网 IP 还是域名）——它和服务器迁移耦合。
- 待决策：D44

### 4. 硬件选型与下单（D23）

- [ ] 定「先买成品小智」还是「ESP32-S3 + 麦克风阵列板」
- [ ] 核对固件支持列表：ESP32-S3、16 MB flash、8 MB PSRAM、麦克风阵列/扬声器
- [ ] 确认供电、外壳、是否要 AEC 参考回采（打断体验取决于它）
- 无硬件可做：只做选型和下单，没有别的

### 5. HTTPS（手机推送与「添加到主屏」）

- 现在只有 `localhost` 是安全上下文；手机用 `http://<LAN IP>:8200` 会同时失去推送和 PWA。
- 方案见 `docs/server-migration.md` 阶段 5；选 Caddy 本地 CA 还是 Tailscale。
- 不解决也能靠设备提醒，但「人不在客厅」时手机就收不到。

## P1：真机前应该做，但不会卡住验收

### 6. 设备端的写操作确认粒度

- `CONFIRM_WRITE_ACTIONS` 是全局开关：开了之后网页每次写也多问一句。
- 客厅场景建议开（一句「要记成…确认吗」比事后纠错便宜），但要确认网页侧能否接受。
- 若不能接受，需要按通道区分（`mcp:` 开、网页关），这是新配置项，别偷偷改语义。

### 7. 声纹身份只到「分会话」这一层

- `_meta` 已验证；现在只用于 `client_id = mcp:<speakerId>`。
- 要叫得出名字、按人隔离记忆，需要 `persons` + `owner`（D40）。可以在设备到位后再做，
  但「谁在说话」的日志最好现在就开始攒（已有 `🔊 MCP 声纹身份` 日志）。

### 8. 小智服务端与 MCP 的联调收尾

- 小智配置里 `mcp_endpoint` 指向小马、`mcp_forward_speaker: true`
- 用数字人页跑一遍：普通闲聊、记提醒、查询、设备控制、打断
- 这一套和反向提醒共用同一个进程，先跑通再打补丁

### 9. HA 还欠一次真实事件验证

- Docker Desktop 当前没起，事件订阅在退避重连
- 门铃/门锁事件只验过传输层（0.46 s），没做过真实触发
- 顺便把「HA 常开」写进运维：开机自启、容器 `restart: unless-stopped`

### 10. 小修小补（低风险，别拖成习惯）

- [ ] 口播时间校验：现在只校验日期，模型仍可能把 15:00 说成 20:00
- [ ] `item_add` 的返回类型映射缺了 `item_add`（结果是 `chat` 而不是 `record`），
      网页侧的展示逻辑要确认一下是不是漏了
- [ ] 评测集：20–30 句固定输入（唤醒/不唤醒、记提醒、改期、删除、查询、设备、歧义、数字），
      每次改编排跑一遍，别只靠手点

### 11. 运维底线

- [ ] 备份脚本 + 恢复演练（迁移清单阶段 7）
- [ ] 日志轮转、systemd 自启、健康检查
- [ ] Linux 上跑一遍 `pytest tests -q`
